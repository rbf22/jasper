## 1. Test-Time Training (TTT) Layers
TTT models treat long-context sequence modeling as a continual learning problem rather than a passive context-retrieval task. [1] 

* The Mechanism: Instead of hiding past data in a static hidden state or expanding a KV cache, a TTT layer uses a standard neural network (like a tiny Transformer or a linear model) as its hidden state. As it reads tokens, it runs a self-supervised next-token prediction gradient update to actively "learn" the context into its own weights. [1, 2, 3, 4] 
* Why evaluate: It achieves true O(1) constant inference latency and memory, yet scales smoothly across long contexts because the model physically fine-tunes itself on the context window during inference. Notable papers to reference include [End-to-End TTT](https://arxiv.org/html/2512.23675) and ByteDance's In-Place TTT. [1, 5, 6, 7] 

## 2. RWKV-7 ("Goose")
The RWKV project remains the gold standard for pure, attention-free linear-time RNNs at scale. [8] 

* The Mechanism: Moving past earlier iterations like Eagle (v5) and Finch (v6), [RWKV-7 "Goose"](https://arxiv.org/abs/2503.14456) introduces a highly generalized delta rule featuring vector-valued gating and dynamic in-context learning rates. [9, 10] 
* Why evaluate: It breaks the classic constraints of linear attention by enabling the state to evolve with intense flexibility. It handles massive context (such as entire book series) in constant memory, routinely matching or outperforming 3B transformer baselines on multilingual and downstream benchmarks while being a fraction of the compute cost. [9, 11, 12] 

## 3. Google's Griffin Architecture (RecurrentGemma)
Google’s official step away from pure Transformers for local/on-device AI. [13] 

* The Mechanism: Griffin blends gated linear recurrences with tiny local sliding window attention blocks. It fixes the recurrent state size to completely cap memory usage. [13, 14] 
* Why evaluate: It powers [RecurrentGemma](https://deepmind.google/models/gemma/recurrentgemma/). It provides an industry-verified production baseline that drastically improves token generation throughput and expands batching capacity, though it trades off some "needle-in-a-haystack" global context precision compared to a full Transformer. [14, 15] 

## 4. Hardware-Aware Linear Attention (Based & LoLCATs)
Spearheaded primarily by Stanford’s Hazy Research group, these models aim to patch the strict "associative recall" failures of traditional linear attention. [16, 17] 

* The Mechanism: Based combines micro sliding window attention (e.g., a window size of just 64 tokens) to nail local syntax, and marries it to a global linear attention mechanism via a Taylor series approximation. LoLCATs focuses on linearizing existing multi-billion parameter Transformers using low-rank adaptation. [16, 17, 18] 
* Why evaluate: Based achieves dramatic speedups—clocking in at 24x the text generation throughput of standard FlashAttention-2—by completely avoiding softmax across the entire sequence. [16, 17]
